## S1a OSS prior-art (pattern axum tranche avec code reel)

**Precedent interne decisif** : `nexus-shell-daemon/src/http.rs:504-516` implemente DEJA en axum 0.8 la topologie exacte demandee — merge de sous-routeurs a layers distincts (`public_routes` sans auth `:254`, `token_route` sans `auth_required` avec Host+Origin verifies DANS le handler `auth_token_public:523`, `authed_routes` avec `.layer(auth_required) :502`), puis `ServeDir::new(root).fallback(ServeFile::new(root.join("index.html")))` en `fallback_service` `:512`.

**(a) Coexistence `GET "/"` + ServeDir — TRANCHE.** Fait load-bearing (passe #2 adversarial) : **axum `route("/")` matche `/` en IGNORANT la query-string**. Il n'existe donc PAS de route distincte « `/?token` » vs « `/` » — un unique `route("/", get(bootstrap))` capture TOUS les hits sur `/`, y compris le `/` post-303 (cookie present, plus de `?token`). Consequence : le handler bootstrap doit lui-meme servir `index.html` (publiquement, le HTML ne porte aucun secret) pour le cas sans `?token`, sinon page blanche. `fallback_service` n'est PAS une route : une route explicite `/` gagne toujours sur lui. ServeDir ne sert donc JAMAIS `/` — il sert uniquement les **assets** (JS/CSS), derriere auth.

**(b) Chicken-and-egg resolu** par merge de sous-routeurs a layers distincts (option (i) du plan, confirmee par Context7 « Applying middleware to specific routes using `Router::merge` » + le daemon `:264`). Le `bootstrap_route` = `Router::new().route("/", get(handle_bootstrap))` **SANS** `.layer(auth_required)` ; merge avec l'`authed` (qui garde son layer `:162-165`). Option (ii) « faire qu'`auth_required` accepte aussi `?token` » REJETEE : le token fuirait dans l'URL/Referer/logs sur CHAQUE requete authed, pas seulement au bootstrap (le daemon ne l'a pas retenue).

**(c) Cookie : parse MANUEL, pas de dep.** `axum-extra`/`cookie`/`tower-cookies` sont ABSENTS du `Cargo.lock`. Coherent avec le style hand-rolled de `auth.rs:21-30` (`is_loopback_host`, `is_loopback_origin`, `constant_time_eq`) — explicitement documente comme duplique pour NE PAS tirer l'arbre de deps daemon. Lecture : `headers.get(header::COOKIE)` -> `to_str()` -> split `';'`, trim, `split_once('=')`, match `"sbfb_operator"`. ~10 lignes, testable comme les helpers existants. A gerer : multi-cookie, valeur vide, absence -> ne JAMAIS fabriquer d'autorite.

**(d) Set-Cookie + 303 — code reel axum 0.8.** `Redirect::to("/")` produit deja un 303 mais ne porte pas le cookie ; utiliser le tuple `(StatusCode::SEE_OTHER, [(SET_COOKIE, "..."), (LOCATION, "/")], Body::empty())` ou `Response::builder()` (forme prouvee par `auth_token_public`). Attributs : `sbfb_operator=<val>; HttpOnly; SameSite=Strict; Path=/`. PAS de `Domain` (host-only par defaut RFC 6265). PAS de `Secure` (loopback http). PAS de `Max-Age`/`Expires` (session-only, D4). Ordre des attributs indifferent (RFC 6265 §4.1).

## S3 threat model

| Menace | Verdict | Mitigation |
|---|---|---|
| **Token-dans-URL** (`?token` en clair) | **P2** local-only | 303 retire `?token` de la barre ; reste dans history/Referer. `build_router` n'a AUCUN `TraceLayer` aujourd'hui (`:122-167`). Mitigations : invariant « ne jamais logger la query-string de `/` » + `Referrer-Policy: no-referrer` sur la reponse bootstrap. Acceptable (attaquant local = deja T0/AD2). |
| **CSRF cross-port loopback** | **P1 — NON adresse par le plan litteral** | SameSite n'est PAS port-scoped : `http://127.0.0.1:9999` et `:3001` sont *same-site* -> le cookie EST envoye. `is_loopback_origin` accepte TOUT port (`auth.rs:202-211`, test `:289`) -> une page hostile sur n'importe quel port loopback pilote `/api/chat/{id}/send` + `/api/artifacts/draft` SANS connaitre le token. Surface NEUVE (l'auth header-only est intrinsequement CSRF-immune). **Correctif (chemin cookie UNIQUEMENT)** : exiger `Sec-Fetch-Site: same-origin` (en-tete forbidden, non-forgeable JS, emis y compris sur GET/SSE/WS same-origin qui omettent Origin). Chemin header inchange (CLI/Vite). NE PAS ajouter `allow_credentials(true)` au CORS. |
| **Cookie cross-port portant le bearer MAITRE** | **P1 — NON adresse par le plan litteral** | Cookies non isoles par port (RFC 6265 §8.5) : un cookie `127.0.0.1` part vers TOUT service loopback visite. Le token (`load_or_generate_token` `auth.rs:99`, doc `:84` « shared with the daemon and coordinator ») = bearer maitre du noeud -> un service web-only SANS acces FS le recolterait (elargit le residu accepte AD2). **Correctif** : la valeur du cookie = **secret de session per-boot distinct de `auth_token`** (genere au boot, stocke dans `AuthState`, compare cote serveur), JAMAIS le token partage. Pin host `127.0.0.1` constant. |
| **Vol de cookie via XSS** | **P2** (surface = front Phase B+) | HttpOnly bloque `document.cookie`. CSP `default-src 'self'` reduit injection/exfiltration. Limite : un XSS same-origin abuse l'API directement (autorite ambiante) sans exfiltrer -> la CSP DOIT exclure `'unsafe-inline'`/`'unsafe-eval'` sur `script-src` sinon cosmetique. Invariant « front greenfield sans inline-script » a poser des Phase A. |
| **DNS rebinding** | **OK — couvert, cookie ne contourne pas** | Host-check tourne EN PREMIER (`:232-239`), cookie lu apres. Apres rebinding le hostname = `evil.com` -> navigateur n'envoie PAS le cookie host-only `127.0.0.1` vers `evil.com`, et `Host: evil.com` echoue `is_loopback_host` -> 403. Double couverture intacte, 0 regression. |
| **CSP self-origin Operator** | **P2 invariant** | Verifier que `'self'` couvre `connect-src` SSE (`operator_server.rs:136`) + `ws://` same-origin terminal (`:145`) : ajouter `connect-src 'self'` explicite (certains navigateurs l'exigent pour `ws://`). Operator HORS `BLOB_SERVE_CSP` scellee (`nexus-core-rs/src/csp.rs:33` ne s'applique PAS a l'Operator). |

## Decisions de conception figees pour le code (prete a coder)

1. **Composition routeur (2 layers distincts).** Construire :
   - `bootstrap = Router::new().route("/", get(handle_bootstrap))` **SANS** `auth_required`.
   - `authed = Router::new().route("/api/...", ...).fallback_service(ServeDir::new(BUNDLE).fallback(ServeFile::new(BUNDLE.join("index.html")))).layer(from_fn_with_state(auth_state, auth_required))` — les routes `/api/*` existantes (`:123-150`) + le ServeDir (assets JS/CSS) sont DERRIERE le cookie/header.
   - `app = bootstrap.merge(authed).layer(csp_layer).layer(cors).with_state(state)`.
   - CORS reste OUTER (statu quo `:166`), `auth_required` INNER. NE PAS ajouter `allow_credentials(true)`.

2. **`handle_bootstrap` (`GET /`, public, hors `auth_required`).** Refaire LUI-MEME le Host-check loopback (`is_loopback_host`, anti-rebind) -> 403 si echec. Si query `?token=<hex>` presente : valider `len==TOKEN_HEX_LEN` + `constant_time_eq` contre `auth.token` ; si valide -> `Set-Cookie: sbfb_operator=<SESSION_SECRET>; HttpOnly; SameSite=Strict; Path=/` + **303 vers `/`** (sans `?token`) + `Referrer-Policy: no-referrer`. Si query absente OU token invalide -> servir `index.html` publiquement (`ServeFile`), reponse **neutre** (PAS d'oracle timing/corps sur la validite du token). Ne JAMAIS retourner de donnees API ici.

3. **`auth_required` — fallback cookie (header D'ABORD).** Apres le bloc Host (`:232-239`) et Origin-si-present (`:241-250`), au 3e check : essayer le header `x-sbfb-token` d'abord (logique `:252-256` inchangee, compare au `auth.token`). Si absent/invalide, essayer le **cookie** `sbfb_operator` (parse manuel de `header::COOKIE`), compare en `constant_time_eq` contre le **secret de session** (decision 4) — ET, sur le chemin cookie UNIQUEMENT, exiger `Sec-Fetch-Site: same-origin` (rejeter 401 sinon ; le chemin header n'exige PAS `Sec-Fetch-Site`). Si ni header ni cookie valides -> 401 (`:258`). Un cookie absent ne fabrique JAMAIS d'autorite.

4. **Valeur du cookie = secret de session per-boot distinct de `auth_token` (G8-PROPOSE, P1-B).** Generer un secret aleatoire (64 hex, meme primitive que `load_or_generate_token`) au boot dans `AuthState` (nouveau champ, ex. `session_secret`). Le `?token` valide pose ce secret en cookie ; `auth_required` (chemin cookie) compare contre lui. Un vol/partage cross-port du cookie ne donne PAS le bearer maitre daemon. D5 ne gele PAS « valeur == token brut » -> additif compatible. (Si le PO refuse l'ajout de champ, fallback = cookie == `auth.token`, mais P1-B reste OUVERT et a documenter comme residu accepte.)

5. **`auth_required` vs bootstrap public** : `GET /` = public (bootstrap + index.html public). `/api/*` + ServeDir assets = derriere `auth_required` (D4 confirme « ServeDir derriere auth = oui »). index.html public au 1er paint (aucun secret) ; les assets exigent le cookie (pose par le bootstrap avant que le navigateur ne les demande).

6. **Duree cookie (D4)** : **session-only** — PAS de `Max-Age`/`Expires`. Host-only (pas de `Domain`). `Path=/`. Pas de `Secure` (loopback http).

7. **Repertoire bundle ServeDir** : constante/param DISTINCT de `repo_root_pub()`. `run_server` (`:171`) passe aujourd'hui `repo_root_pub()` a `build_router` pour les ops git/process (`OperatorState.root:39`) — **NE JAMAIS** pointer ServeDir dessus (exposerait tout le repo). Ajouter un param `bundle: PathBuf` (ou Option) a `build_router`, resolu dans `run_server` depuis un emplacement dedie (constante nommee, ex. dossier dist Operator), JAMAIS la racine repo, JAMAIS `tools/factory-operator/dist` (voue a la poubelle Phase B). SPA fallback : `ServeDir::new(bundle).fallback(ServeFile::new(bundle.join("index.html")))`. Le front greenfield arrivant en Phase B, le bundle peut etre absent en Phase A -> ServeDir renvoie 404 (l'auth passe quand meme) ; les tests fournissent une fixture tempdir avec `index.html` minimal.

8. **CSP** : middleware `from_fn` en layer **OUTER** sur le routeur ENTIER (couvre aussi 401/403/404), pattern `blob_serve_csp_middleware` (`http.rs:251`). Chaine Phase A minimale : `default-src 'self'; connect-src 'self'` (couvre SSE + `ws://` same-origin). `script-src` repose sur `default-src 'self'` -> JAMAIS `'unsafe-inline'`/`'unsafe-eval'` (invariant pose des maintenant). `style-src`/`img-src` durcis Phase E (Tailwind v4/Motion). Operator HORS `BLOB_SERVE_CSP` scellee.

9. **Parse cookie** : MANUEL (decision S1a-c), 0 dep. Gerer multi-cookie, valeur vide, absence ; pas de decodage URL (token/secret = hex pur).

10. **Tests a ajouter (Rust integration des Phase A, Playwright Phase B)** : cookie valide -> auth passee (non-401/403) ; cookie invalide -> 401 ; header gagne sur cookie contradictoire ; `GET /?token` valide -> 303 + `Set-Cookie` correct ; `?token` invalide -> pas de cookie + reponse neutre ; cookie absent + header absent -> 401 (figer que le fallback ne fabrique pas d'autorite) ; chemin cookie sans `Sec-Fetch-Site: same-origin` -> 401 ; bootstrap Host non-loopback -> 403. Fixture index.html minimal pour asserter 200 vs simplement « pas 401 ».

11. **Livrable doc BLOQUANT** : amender `docs/security/THREAT_MODEL.md:800-821` (T-OPERATOR-CSRF) — le cookie ambiant falsifie `:813` ; documenter SameSite=Strict + `Sec-Fetch-Site: same-origin` + secret de session distinct comme nouvelle base de mitigation, et les residus token-in-URL (history/Referer) + cross-port.
