## 1. Threat Model Summary

The project uses a formal STRIDE + LINDDUN threat model documented in `docs/security/THREAT_MODEL.md` (written Sprint 16, updated Sprint 29). The methodology follows OWASP Threat Dragon patterns with Microsoft STRIDE for technical threats and KU Leuven LINDDUN for privacy (GDPR).

**Adversary Model (5 personas):**

| ID | Persona | Key Capability |
|---|---|---|
| AD1 | Malicious browser extension | `host_permissions: "http://localhost/*"` |
| AD2 | User-mode malware | Read/write home dir (no root) |
| AD3 | Byzantine P2P node | Remote QUIC peer, gossip spam/forgery |
| AD4 | Git repo squatter | Backdoored commits in public repos |
| AD5 | Malicious app publisher | Crafted `task_submit` payloads via bridge |

**Assets protected:**
- `A1` Ed25519 keypair (`~/.sbfb/daemon.key`) — **Critical**
- `A2` Bearer token (`~/.sbfb/auth_token`) — **High**
- `A3` Provenance signatures — Integrity **Critical**
- `A4` User consent preferences (`consent.json`)
- `A5` GPU usage counters
- `A6` Project archives (zip blobs, BLAKE3-verified)
- `A7` Kudos ledger (hash-chain append-only)

## 2. Loopback HTTP Hardening

**Implementation:** `crates/nexus-shell-daemon-core/src/auth.rs`

### 2.1 Three-Check Middleware

Every HTTP request (except `/health`) passes through `auth_required()` middleware that enforces three checks in sequence:

1. **Bearer token** (`X-SBFB-Token` header): 256-bit CSPRNG hex token, constant-time comparison via custom `constant_time_eq()` at line 461. Generated by `generate_token()` using `OsRng.fill_bytes()`. Stored at `~/.sbfb/auth_token` with mode 0600 on Unix.

2. **Host header allowlist**: `is_loopback_host()` at line 239 accepts only `localhost`, `127.0.0.1`, `[::1]` (with optional port). Blocks DNS rebinding attacks (CVE-2025-49596 pattern from Anthropic MCP Inspector, CVSS 9.4).

3. **Origin header check**: `is_loopback_origin()` at line 274 accepts only `http://` loopback origins. Absent Origin is OK (CLI/curl). HTTPS loopback is explicitly rejected (daemon is HTTP-only). Blocks cross-origin fetches from malicious web pages.

### 2.2 Token Rotation (Sprint 18 Phase D)

`TokenRotator` at line 529 supports rotation with a 10-minute overlap window (`TOKEN_OVERLAP_DURATION = 600s`). The launcher writes `tokens.json` (current + previous pair). `TokenRotatorWatcher` at line 709 spawns a background `notify::RecommendedWatcher` thread that hot-reloads `tokens.json` on filesystem changes with 50ms debounce. Poisoned `RwLock` collapses to `false` (fails closed).

Persistence format: `TokensFile` with `current`, `previous`, `rotated_at` fields, atomic write via tempfile+rename.

### 2.3 Peer Credentials Bypass (Sprint 16 Phase B)

`PeerCredsVerified` marker at line 381 is a private type injected into axum request extensions by the UDS/Named Pipe accept loop when OS-level peer credentials match (SO_PEERCRED on Unix, DACL-restricted Named Pipe on Windows). Cannot be spoofed via HTTP headers because axum strips extensions from the public Request type.

- **Unix**: `crates/nexus-shell-daemon/src/uds_server.rs` (366 LOC) — SO_PEERCRED rejects uid != geteuid()
- **Windows**: `crates/nexus-shell-daemon/src/named_pipe_server.rs` (417 LOC) — DACL via SDDL `D:(A;;GA;;;<sid>)`

### 2.4 Test Coverage

18 tests in `auth.rs`: bearer validation, Host/Origin allowlists, IPv6 loopback, PeerCredsVerified bypass, PeerCredsVerified non-leak via HTTP, token generation, idempotent load-or-generate, malformed file rejection, Unix permissions verification.

## 3. Iframe Sandbox & Blob-Serve Isolation

**Implementation:** `crates/nexus-shell-daemon-core/src/blob_serve.rs`

### 3.1 Content Security Policy

Defined as `BLOB_SERVE_CSP` constant at line 277:
```
default-src 'self' 'unsafe-inline' 'unsafe-eval' data: blob:;
connect-src 'none';
worker-src 'none';
frame-src 'none';
object-src 'none';
base-uri 'none';
form-action 'none';
frame-ancestors *;
sandbox allow-scripts
```

Key restrictions:
- `connect-src 'none'` — scripts inside iframe cannot make outbound network requests
- `worker-src 'none'` — prevents Service Worker registration
- `frame-src 'none'` — blocks nested iframes (the `/auth/token` exfiltration vector)
- `form-action 'none'` — blocks form-based exfiltration that `connect-src 'none'` does not cover
- `sandbox allow-scripts` — gives opaque origin even in top-level tab (blocks localStorage, cookies on daemon origin)

### 3.2 Cross-Origin Isolation Headers

- `BLOB_SERVE_COOP: "same-origin"` — isolates browsing context group
- `BLOB_SERVE_COEP: "require-corp"` — blocks cross-origin resources lacking explicit CORP opt-in

### 3.3 Archive Security

- **Path traversal rejection**: `validate_zip_path()` at line 181 refuses `..`, absolute paths, backslash escapes, empty paths
- **Zip bomb defense**: `DEFAULT_MAX_DECOMPRESSED_BYTES = 100 MB` — archives exceeding this are rejected during decompression
- **LRU cache**: `BlobServeCache` with configurable `max_entries` (default 32), evicts oldest on overflow

### 3.4 Iframe Origin Separation

Blob-serve runs on a separate origin (port 7000) from the shell (port 5173/8765) and coordinator (port 8080). The browser enforces same-origin policy isolation: iframe cannot access shell's cookies, localStorage, or DOM.

### 3.5 Test Coverage

16 tests in `blob_serve.rs`: path traversal rejection (3 variants), absolute path, backslash, empty path, valid paths, content-type detection (6 variants), zip load/retrieve, invalid zip rejection, oversized archive rejection, path traversal in zip, cache eviction.


### 4.2 Schema Validation

Every incoming message is validated against `BridgeRequestSchema` (Zod):
- `type`: must be literal `"sbfb-bridge-request"`
- `id`: must be UUID (correlation ID for reply matching)
- `method`: must be in whitelist enum
- `payload`: record of unknown values (method-specific validation downstream)

### 4.3 Source Validation

The `useBridge` hook validates `event.source === iframe.contentWindow` to ensure messages originate from the expected iframe, not from injected scripts or other windows.

### 4.4 CPU Watchdog (Sprint 15 Phase B)

`WatchdogState` at `useBridge.ts:46` tracks iframe health:
- `unknown` -> `healthy` on first heartbeat
- `healthy` -> `stalled` if no heartbeat for `STALL_THRESHOLD_MS = 5000ms`
- Stalled iframe gets "Application ne repond plus" overlay
- Check interval: 2000ms

### 4.5 Heartbeat Protocol

`BridgeHeartbeatSchema`: `type: "sbfb-bridge-heartbeat"`, `ts: positive number`. Fire-and-forget, no reply expected.

### 4.6 PII Redaction (Sprint 21)

`PII_REDACT_MAX_TEXT_LENGTH = 50_000` bytes hard cap on text submitted for redaction. Client-side PII redaction via `pii_redact` bridge method dispatched locally in host shell (no coordinator round-trip).

## 5. Cryptographic Primitives

**Implementation:** `crates/nexus-core-rs/src/crypto.rs`, `crates/nexus-core-rs/src/canonical.rs`

### 5.1 Ed25519

- Library: `ed25519-dalek` (from `Cargo.toml`)
- Key generation: `OsRng.fill_bytes()` (CSPRNG)
- Key format: 32-byte secret, 32-byte public, 64-byte signature
- Key persistence: `KeyPair::load_or_generate()` — raw 32-byte binary blob, mode 0600 on Unix
- Used for: node identity, task/result/claim signing, curator list signing, provenance signing, canary signing, key rotation, feed entry signing

### 5.2 BLAKE3

- Library: `blake3` crate
- 32-byte digest
- Used for: archive integrity (iroh-blobs verify on retrieval), hash-chain ledgers (`Blake3Chain`), topic ID derivation, provenance hashing
- `Blake3Chain`: append-only hash chain `H_{i+1} = BLAKE3(H_i || entry_i)` — tamper-detection for kudos ledger and public feed

### 5.3 Domain Separation (JCS + Prefix)

`canonical_bytes()` at `canonical.rs:220` produces:
```
<domain bytes> <0x00> <serde_jcs::to_vec(value)>
```

13 domain tags defined, each preventing cross-type signature replay:
- `DOMAIN_TASK_V1`, `DOMAIN_RESULT_V1`, `DOMAIN_CLAIM_V1`
- `DOMAIN_INVITE_V1`, `DOMAIN_KUDOS_V1`, `DOMAIN_CURATOR_LIST_V1`
- `DOMAIN_PROVENANCE_V1`, `DOMAIN_WARRANT_CANARY_V1`
- `DOMAIN_POW_V1`, `DOMAIN_DURESS_ACK_V1`
- `DOMAIN_AGE_WITNESS_V1`, `DOMAIN_CONTRIBUTOR_ATTESTATION_V1`
- `DOMAIN_KEY_ROTATION_V1`, `DOMAIN_DELEGATION_CERT_V1`, `DOMAIN_FEED_V1`

JCS (RFC 8785) ensures cross-language byte-identical serialization (Rust `serde_jcs` + Python `jcs` PyPI).

### 5.4 Encryption at Rest (Sprint 20)

`crates/nexus-core-rs/src/keystore.rs` implements double-layer defense:
1. **PIN layer**: Argon2id (m=64 MiB, t=3, p=1) derives `kek1` from user PIN
2. **OS keyring layer**: 32-byte `kek2` stored in macOS Keychain / Windows Credential Manager / Linux Secret Service
3. **Final key**: `BLAKE3(DOMAIN || kek1 || kek2)` — both needed to decrypt
4. **Blob format v1**: magic `SBFBK1`, AEAD-sealed secret key
5. **Zeroization**: `SecretBox<[u8; 32]>` with `zeroize` crate — keys zeroed on drop

## 6. Proof of Work (Sybil Resistance)

**Implementation:** `crates/nexus-core-rs/src/pow.rs`

### 6.1 Hashcash SHA256

- Publisher-bound: `publisher_pubkey` in challenge prevents cross-identity replay
- Topic-bound: `topic` field prevents cross-topic replay
- Time-bound: `issued_at` + `MAX_PROOF_AGE_SECS = 1800` (30 min) prevents indefinite replay
- Default difficulty: `DEFAULT_DIFFICULTY_BITS = 18` (2^18 ~ 100ms on modern CPU, Tor rend-point PoW baseline)
- Maximum difficulty: `MAX_DIFFICULTY_BITS = 30` (safety cap)
- Solver timeout check every 1024 iterations

### 6.2 Escalating Difficulty

`EscalatingPolicy` at line 447: geometric ramp per (consumer, model) tuple.
- Formula: `base_difficulty * multiplier^(task_count / tranche_size)`
- Daily midnight UTC reset via `should_reset_daily()`
- Overflow saturation: exponent capped at i32::MAX, result clamped to max_difficulty

### 6.3 Verification

- `verify_stateless()`: hash match + leading-zero-bits check (pure function, no I/O)
- `verify_at()`: adds freshness bounds (rejects expired + future proofs)
- `verify()`: uses current system clock

### 6.4 Test Coverage

26 tests in `pow.rs`: solve+verify happy path, tampered nonce/hash rejection, downgraded difficulty, difficulty zero trivial, timeout on over-difficulty, different topics/publishers yield different solutions, future/expired proof rejection, canonical bytes determinism, leading zero bits boundaries, unknown version rejection, difficulty clamping, escalating difficulty (8 tests), daily reset boundaries.

## 7. 3-Layer Verification System

**Implementation:** `crates/nexus-core-rs/src/verification.rs`

### 7.1 Layer 1 — Ed25519 Signature (WHO)

- Verifies cryptographic identity via `ResultEntry::verify_signature()`
- Failure: trust -50 + auto-ban (critical: stolen key or active forgery)
- Latency: ~0.1ms

### 7.2 Layer 2 — Model Digest Whitelist (WHICH)

- BLAKE3 of the model NAME compared against approved digests (S76 Phase C doc-note: a real weights-file digest is gated on `llm_llama_cpp`, S77; `Verifier` has no live caller — the live path is the quorum over `result_text`)
- Empty whitelist = pass with `NoWhitelist` reason
- Mismatch: trust -50 + auto-ban (critical)

### 7.3 Layer 3 — Logprob Fingerprint (DID)

- BLAKE3 hash of canonical logprob fingerprint vs registered reference
- Mismatch: trust -5 (suspect, not critical), no ban
- Enables subsequent spot-check dispatch

### 7.4 Spot-Check Rate Table

```
trust >= 80: 1% (trusted)
trust >= 50: 5% (standard)
trust < 50:  20% (suspect)
```

### 7.5 Test Coverage

8 tests: valid signature acceptance, tampered signature ban, digest whitelist match/mismatch, unprofiled model pass, logprob hash match/mismatch, spot-check rate tiers.

## 8. Key Rotation

**Implementation:** `crates/nexus-core-rs/src/key_rotation.rs`

### 8.1 Protocol

- `KeyRotationAnnouncement` signed by **old key** (proves possession)
- Contains `old_public_key`, `new_public_key`, `timestamp`, `reason`, `transition_days`

- Domain: `DOMAIN_KEY_ROTATION_V1`

### 8.2 Transition Window

- Default: 7 days, max: 90 days
- During window: both old and new keys accepted
- After window: old key fully revoked
- Stale rotations (timestamp <= existing) rejected by `RevocationCache`

## 9. Warrant Canary (FROST DKG)

**Implementation:** `crates/nexus-shell-daemon-core/src/canary/`

### 9.1 Canary System

- Monthly signed declaration: maintainer has NOT received gag orders / been compelled to backdoor
- Dead-man-switch: missed publication > 45 days = alarm
- Format: `CanarySigned` + Ed25519 signature over `canonical_bytes(signed, DOMAIN_WARRANT_CANARY_V1)`
- Wire: JCS canonical JSON broadcast on gossip topic `blake3(b"nexus-grid/warrant-canary/v1")`
- Repo mirror: `CANARY.txt` via `format_canary_txt()` / `parse_canary_txt()` (offline-verifiable)
- Headline cap: `MAX_HEADLINE_LEN = 512` bytes (DoS defense)
- Signing key: persistent Ed25519 at `~/.sbfb/canary-key.key` (distinct from daemon identity)

### 9.2 FROST K-of-N Threshold Signing

`crates/nexus-shell-daemon-core/src/canary/frost.rs`:

- RFC 9591 FROST-ed25519 via `frost-ed25519` crate (ZcashFoundation, Trail of Bits audit 2023)
- Default config: K=2/N=3 (2 of 3 maintainers needed)
- Aggregated signature is byte-identical to standalone Ed25519 — verifier path unchanged
- Threat coverage:
  - T-canary-key-exfil: attacker needs K=2 maintainers simultaneously
  - T-canary-gag-order: single subpoenaed maintainer cannot prevent canary publication (K-1 non-coerced maintain signing capability)
- `frost_keygen_trusted_dealer()`: produces N key shares + shared pubkey
- `frost_sign_with_shares()`: round-1/round-2/aggregate sequence
- K=1 rejected per RFC 9591 section 6.1 (degenerate threshold)

### 9.3 Duress Acknowledgement

`crates/nexus-shell-daemon-core/src/canary/duress_ack.rs`:
- Daily heartbeat signed with maintainer key
- Separate gossip topic + domain tag `DOMAIN_DURESS_ACK_V1`
- Cross-stream replay impossible (different domain tags)

### 9.4 Test Coverage

16 tests across canary modules: build/verify, tampered message/pubkey rejection, gossip broadcast round-trip, JCS canonical cross-language guarantee, headline cap, canary.txt round-trip, FROST K=2/N=3 valid Ed25519, FROST K=2/N=2 minimum, K=1 rejection, partial-below-threshold refusal, tampered share rejection, FROST-vs-standalone-Ed25519 interop verification.

## 12. Output Filter

**Implementation:** `crates/nexus-coordinator-rs/src/output_filter.rs`

### 12.1 Detection Layers

1. **Invisible text steganography**: `is_invisible_char()` detects zero-width chars (U+200B-200F, U+2060, U+FEFF), Private Use Area (U+E000-F8FF, supplementary PUA), Unicode tags (U+E0020-E007F). BiDi format chars (U+202A-202E, U+2066-2069) are preserved.

### 12.2 Risk Scoring

- Exact prompt echo: 1.0
- Substring prompt echo: 0.8
- Edit distance echo: 0.7
- Clean: 0.0

- T3: CA compromise

### 20.2 Pin Validation Policy

| State | Behavior |
|---|---|
| Pinset absent/empty | Fail-open + tracing::warn (pre-launch convivialite) |
| Pinned + SPKI match | Accept |
| Pinned + SPKI mismatch | Reject (`PinError::SpkiMismatch`) |
| Pinned URLs exist but this URL not pinned | Reject (`PinError::NoPin`) |
| All pins expired | Reject with `any_expired = true` |

- RFC 7469 section 2.4 SPKI SHA-256 base64url-no-padding fingerprint
- Hot-reload via `notify` watcher (pattern from ConsentWatcher/TokenRotator)

- **Still open**: CI `cargo-audit` / `npm audit` not yet wired as blocking gates

- **Still open**: N clones/min rate limit not implemented

- **Still open**: rotatable contribution_id per project deferred to v2+
